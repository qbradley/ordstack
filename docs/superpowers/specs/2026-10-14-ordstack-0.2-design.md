# ordstack 0.2 — design

Status: draft for review, 2026-10-14. Extends
[`2026-10-13-ordstack-design.md`](2026-10-13-ordstack-design.md) (the 0.1
spec, "the spec" below), whose section 10 outlines 0.2. Inputs: that
outline, and the ten API workarounds recorded by the benchmark ports in
[`bench/RESULTS.md`](../../../bench/RESULTS.md) ("feedback 1–10").

Everything in the spec still holds: the guarantee (section 1), the model,
the verification suites, the machine rules. 0.2 adds API; it changes no
existing signature and no existing behaviour.

Each plan is written when the previous one has landed, against the code as
it then is (the spec's rule: "each item gets its own plan"). Order:
0.2a → 0.2b → 0.2c → 0.2d → 0.2e. 0.2b and 0.2c are independent of each
other; 0.2d needs both (maps and the derive crate); 0.2e needs all.

Not in 0.2, by decision:

- **Counters for in-place grows and bytes copied** (feedback 6, second
  half). They would put a counter update on every allocation and growth for
  a measurement need the benchmark met from `extent`/`high_water`. Revisit
  only if a user asks.
- **A smaller default reservation** (feedback 9). 4 GiB of address space is
  free on 64-bit Linux; the cost appears only under `ulimit -v`, and there
  `Stack::with_reserve` is the answer. A6 documents it.
- **Automatic reclamation instead of `Stack::reset`** (feedback 7) and **a
  growing child without a second stack** (feedback 8). Both are the design,
  not gaps; A6 documents the patterns.
- **The `by_bucket` shape** (vectors that grow round-robin). Not
  expressible on a stack; stays on the heap, as the spec's model says.

## 2. Plan 0.2a decisions

**A1 `sformat!`.** `sformat!(frame_expr, fmt, args...)` expands to an
`SString` built on `frame_expr` (which must evaluate to `&mut Frame<'f>`),
written with `core::fmt::Write::write_fmt`, then frozen. Returns
`SStr<'f>`. Panics if the stack is exhausted (as `push_str` does) or if a
`Display` impl returns an error (as `format!` does). No new `unsafe`.

**A2 iteration.** Borrowed forms return `core::slice::Iter` /
`IterMut`. `SFixedVec` by value is `into_slice().into_iter()`, the existing
`iter::IntoIter<'f, T>`. `SVec` by value gets a new `iter::VecIntoIter<'v,
'f, T>` that keeps holding the vector's frame, so the buffer is not frozen:
once the iterator is gone, the space above the frame is reclaimed lazily
like any dropped vector. (Freezing first would pin the buffer below
`frame.end` until the frame's parent is reused — the memory behaviour that
made the serde port call `Stack::reset` by hand.) It wraps an
`iter::IntoIter<'v, T>` built from the vector's raw parts: one new `unsafe`
block, argued in `SOUNDNESS.md` like `SVec::freeze`.

**A3 `alloc_slice_from_iter`.** `Frame::alloc_slice_from_iter<T>(&mut
self, iter: impl IntoIterator<Item = T>) -> SSlice<'f, T>` is
`SVec::from_iter_in(iter, self).freeze()`: the vector is on top, so it
grows in place and is frozen without a copy. No `ExactSizeIterator` bound
and no new `unsafe`. The iterator cannot allocate from the same frame
(it is borrowed); that is what `CloneIn` (0.2c) is for.

**A4 `Frame::stack`.** `pub fn stack(&self) -> &Stack`. Through `&Stack`
only `capacity`, `extent`, `high_water` and `Debug` are reachable; all
read `Cell`s. The returned borrow is bounded by the frame borrow. No new
`unsafe`. Also available through containers' `above()` frames; no
container method is added.

**A5 `#[inline]`.** On `Stack::{set_top, reset_to, try_bump, try_extend,
ptr_at, offset_of}` and `Frame::try_alloc_array`'s non-generic callees.
Kept only if `bench/run.sh` shows the ordstack variants no slower (median
within IQR or better) on all four cases; the numbers go into
`bench/RESULTS.md` as a dated addendum either way.

**A6 Patterns.** Three doctested sections in the crate docs and a README
pointer: (1) phases — build, consume, `Stack::reset` or `trim`, build
again; (2) a growing child — collect on a scratch stack, `freeze_into` the
long-lived one; (3) reservations — what `Stack::new` reserves, why it is
free on 64-bit Linux, and `with_reserve` under `ulimit -v` or Miri.

## 3. Decisions fixed now for later plans

These shape public types, so they are fixed here; each later plan details
them against the code as it then is.

**B maps.** As the spec's outline: insertion-ordered; one block holding the
entries `(hash: u64, K, V)` followed by an index table of `u32` slots
(0 = empty, otherwise entry index + 1), open addressing with linear probing,
load factor at most 7/8. Growth extends the block in place, leaves entries
where they are, and rebuilds the index at its new offset from the stored
hashes (no rehashing of keys). Removal: `swap_remove` and `shift_remove`,
backward-shift deletion in the index. At most `u32::MAX - 1` entries.
Hasher `S: BuildHasher` with default `std::hash::RandomState`; iteration
order is insertion order, so output never depends on the hasher. API
follows `indexmap` names where a counterpart exists (`insert`, `get`,
`get_mut`, `get_index`, `contains_key`, `entry` with `or_insert`/
`or_insert_with`/`or_default`, `iter`, `keys`, `values`, `len`, `freeze`,
`freeze_into`). Drops entries back to front.

**C `CloneIn`.**

```rust
pub trait CloneIn<'f> {
    type Cloned;
    fn clone_in(&self, frame: &mut Frame<'f>) -> Self::Cloned;
}
```

Implemented explicitly (a macro, not a blanket impl over `Clone`) for the
primitives, `String`-free std leaf types (`bool`, `char`, integers, floats,
`()`), `Option<T>`, tuples up to 4, `SStr` (`→ SStr<'f>`), `SSlice<T:
CloneIn>`, `SBox<T: CloneIn>`, `SFixedVec`, `SFrozenMap`. A blanket impl
would make `Option<SStr>` impossible, since `Option<T>` would then be
covered twice. Slices clone into an `SFixedVec` of exact capacity first
(a frozen block, so the frame stays free) and then clone each element onto
the frame above it — no scratch stack is needed because the length is
known. `ordstack-derive` (a second crate in the workspace, proc-macro,
depends on `syn`/`quote`) derives it for structs and enums; a field
attribute `#[ordstack(clone)]` uses `Clone::clone` for a field whose type
has no `CloneIn` impl.

**D serde.** Feature `serde` (off by default) on `ordstack`.

- `Serialize` for `SStr`, `SString`, `SSlice`, `SVec`, `SFixedVec`,
  `SBox`, `SMap`, `SFrozenMap`.
- Deserialization takes two frames, because a sequence of unknown length
  whose elements also allocate cannot grow on the frame its elements use:

  ```rust
  pub struct De<'a, 'f, 's> {
      pub data: &'a mut Frame<'f>,    // where results live
      pub scratch: &'a mut Frame<'s>, // where sequences grow
  }
  pub trait DeserializeIn<'f>: Sized {
      fn deserialize_in<'de, D: serde::Deserializer<'de>>(
          cx: &mut De<'_, 'f, '_>,
          d: D,
      ) -> Result<Self, D::Error>;
  }
  ```

  A sequence collects into an `SVec` on `scratch`; each element is
  deserialized with `scratch` replaced by that vector's `above()` frame, so
  nesting recurses up the scratch stack; the finished vector is
  `freeze_into(data)` (one bitwise copy per sequence). Strings go straight
  to `data`. Stock impls as for `CloneIn` (explicit, not blanket), plus
  `#[ordstack(owned)]` to deserialize a field with plain
  `serde::Deserialize`. A seed type `In<'a, 'b, 'f, 's, T>(&'a mut De<'b,
  'f, 's>, PhantomData<T>)` implements `DeserializeSeed` for use with
  `serde_json::Deserializer` directly.
- `#[derive(DeserializeIn)]` in `ordstack-derive` for structs with named
  fields, tuple structs and externally tagged enums, accepting both map and
  sequence forms like serde's derive. Attributes in 0.2: `rename` and
  `owned`. Anything else is a compile error naming the attribute.

**E acceptance.** As the spec's section 10, in `bench/`: the three
programs rewritten against 0.2 with no `unsafe` and no hand-written
visitor, identical output, line counts and the share of bytes served from
stacks reported beside the 0.1 ports' figures, and the benchmark re-run.

## 4. Verification for every 0.2 plan

Unchanged from the spec: every new public function gets a row in
`SOUNDNESS.md`'s per-function table; every new `unsafe` block a row in the
unsafe table (`scripts/check-unsafe-table.sh`); every rejection a new
public item depends on gets a compile-fail case with its passing twin; the
model test and fuzz target gain operations for new growable types;
`scripts/check.sh` passes on the train box. Heavy runs never on the EC2
box.
